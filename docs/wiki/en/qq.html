QQ bot

This is an Nascraft26P addition; upstream Nascraft does not have it. It lets players look up prices, set alerts and link accounts in QQ groups, and posts trades into groups.

Three ways to connect — pick the one that matches your QQ setup (you can even enable several at once, each is described below):

Way Best for What you need
OneBot v11 (personal QQ) A personal QQ account, your own bot framework A OneBot v11 implementation (NapCat / LLOneBot / Lagrange / go-cqhttp, ...)
Official QQ bot (open-platform API v2) Official channels, long-term stability AppID and AppSecret from the QQ open platform
Official QQ bot + OneBot adapter You already run onebots and want to reuse one adapter Node.js + @onebots/adapter-qq (a OneBot v11 wrapper around the official SDK)

All ways share the same QQ commands and account linking: a code generated by /linkqq works everywhere.

What it can do

Feature Description
Price quotes Send 行情 coal in a group or private chat to get price, stock and today's change
Price alerts Get a private message when a price is reached, up to 8 per QQ account
Trade announcements Large trades and trades of chosen players are pushed to configured groups in real time
Account linking One-to-one QQ ↔ game account linking, permissions match the in-game ones

Way 1: OneBot v11 (personal QQ)

Supported implementations

The protocol is plain OneBot v11, so in principle anything works:

  • Personal QQ: NapCat, LLOneBot, Lagrange, go-cqhttp
  • Official QQ bot channels: gensokyo, @onebots/adapter-qq and other OneBot v11 adapters

The bot is not bundled with the plugin; deploy one yourself and enable its HTTP API and HTTP reporting.

Configuration

The onebot section at the end of config.yml:

onebot:
  enabled: false
  # OneBot v11 HTTP API address (no /send_private_msg suffix)
  api-url: 'http://127.0.0.1:3000'
  # access token agreed with the OneBot implementation; empty means no check
  access-token: ''

  # broadcast in-game trades to QQ groups
  log-trades:
    enabled: false
    # group ids receiving the trade log, several allowed
    group-ids: []

  # QQ price alerts
  alerts:
    enabled: false
    # how often alerts are checked (seconds)
    check-interval: 60

  # webhook server receiving OneBot event reports
  webhook:
    enabled: false
    host: '127.0.0.1'
    port: 8765
    path: '/onebot'
    # secret used to verify reports; empty or SECRET means no check
    secret: ''

  # commands allowed from QQ
  commands:
    enabled: true
    # groups allowed to use commands; empty = all groups (private chat always allowed)
    group-whitelist: []

Keep port away from other plugins (web maps, panels) — the plugin listens on it itself.

Connecting

  1. Deploy the bot (NapCat / LLOneBot for example) and log in with your QQ account.
  2. Enable HTTP service (HTTP API) in its dashboard, note the address and port, and preferably set an access token.
  3. Configure HTTP reporting (HTTP POST) in the dashboard, pointing at:

http://<server LAN or public IP>:8765/onebot

If webhook.secret is not empty, fill the same token / secret on the bot side.

  1. Back in config.yml, enable onebot.enabled and webhook.enabled, set api-url and restart the server.
  2. [OneBot] Webhook listening on http://…:8765/onebot in the console means it is up.

Linking an account

  1. In game the player runs /linkqq (alias /qq, permission nascraft.qq.linkable).
  2. The plugin answers with a 6 digit code, valid for 10 minutes.
  3. The player private messages the bot on QQ with 绑定 123456 (or bind 123456).
  4. Once linked, quotes and alerts go to that QQ account.

Unlink:

  • In game: /linkqq unlink
  • On QQ: 解绑

QQ commands

Send them in a private chat, or in a group where the bot can be addressed (or any group on the whitelist).

Command Description
帮助 / help / 菜单 / ? Show command help
行情 <item> / 价格 <item> / price <item> Price, stock and today's change
提醒 <item> <price> / alert <item> <price> Set a price alert (negative = drop below)
提醒列表 / alerts List your alerts
取消提醒 <item> / unalert <item> Remove an alert
绑定 <code> / bind <code> Link your game account
解绑 / unlink Unlink

Examples:

行情 煤炭
提醒 钻石 120
提醒列表

Trade announcements

With onebot.log-trades.enabled on and group-ids filled, every trade is posted as:

[TIME] [PLAYER] [ACTION] [AMOUNT] x [ITEM] = [WORTH]

Customize the wording with onebot_trade_line in langs/zh_CN.yml; placeholders such as [ACTION] are substituted.

Troubleshooting

Symptom What to check
No reaction to commands in a group Is webhook.enabled on? Does the bot report to http://IP:port/onebot?
403 webhook.secret does not match the token on the bot side
405 The report used GET; it must be POST
Messages arrive but replies do not Wrong api-url, or the bot's HTTP API is off
Works in groups but not in private chat Private messages use the same webhook; check the bot reports them too
"This QQ is already linked" One QQ per game account — run 解绑 on QQ first
Startup log 端口 127.0.0.1:8765 已被占用 Another plugin/process on the same machine already uses that port (most often another QQ bot plugin with its own webhook/HTTP server). Change onebot.webhook.port (for example to 8766) and update the bot's report URL; or set onebot.webhook.enabled: false when you do not need QQ commands
Startup log onebot.webhook.enabled=false：QQ 命令与「绑定」都不会生效 QQ commands require onebot.webhook.enabled; trade announcements and alerts do not

The server must be able to reach the bot: if they are not on the same machine, api-url needs a reachable address (or a tunnel).

Way 2: official QQ bot (open-platform API v2)

Added in v26.4.5.2: no third-party client such as NapCat needed — the plugin talks to Tencent's gateway directly with HttpClient + WebSocket.

Differences from OneBot

OneBot v11 Official QQ bot
Extra client required yes (NapCat / LLOneBot…) no, the plugin connects itself
Entry barrier any QQ account register as a developer on q.qq.com, create a bot and pass review
Identity QQ number openid (not a QQ number, differs per bot)
Proactive messages basically unlimited subject to official rate limits (passive replies valid for 5 minutes, up to 5 per message)
Group id QQ group number group openid

The two ways can run at the same time: codes from /linkqq work for both, and links are stored separately in onebot.yml and qqofficial.yml.

This way binds no local port: the plugin connects out to Tencent's gateway (outbound WebSocket + HTTPS), so it neither listens on HTTP nor needs port forwarding — it cannot clash with another QQ bot plugin over a port, and nothing has to be opened in the firewall. Only the OneBot webhook from way 1 listens on a port.

Configuration

qq-official:
  enabled: false
  # bot AppID / AppSecret (from "Development settings" on the open platform)
  app-id: ''
  client-secret: ''
  # set true during review/development to use the sandbox
  sandbox: false
  # custom API base; empty picks one based on sandbox
  api-base: ''
  # custom token endpoint; empty uses the official one (with fallback)
  token-url: ''
  # subscribed event bitmask; 33554432 = 1<<25 (group @-messages + private messages)
  intents: 33554432
  log-trades:
    enabled: false
    # group openids (not group numbers)
    group-openids: []
  alerts:
    enabled: false
    check-interval: 60
  commands:
    enabled: true
    # group openids allowed to use commands; empty = all
    group-whitelist: []

Connecting

  1. Open the QQ open platform, create a bot and note the AppID and AppSecret.
  2. Under "Development settings" request the permissions you need, and make sure the group @-message and private message events are granted (intents 1<<25).
  3. Add the bot to the target QQ groups (it must be a member to reply passively).
  4. Fill in the qq-official section of config.yml, set enabled: true and restart the server.
  5. [QQ Official] 已连接 QQ 网关 in the console means it is connected (the first connection also prints 鉴权成功 (session=…)).
  6. During the sandbox phase set sandbox to true.

Getting the group openid

A group openid is not the group number. After adding the bot, @-mention it in the group with 帮助; the received group_openid appears in the console/plugin warnings. You can also link and query prices in a private chat first.

Commands

Identical to OneBot: 帮助, 行情 <item>, 提醒 <item> <price>, 提醒列表, 取消提醒 <item>, 绑定 <code>, 解绑. In groups the bot must be @-mentioned.

Troubleshooting

Symptom What to check
Console keeps reconnecting Are app-id / client-secret correct? Has the bot passed review?
Gateway reports an intents error and closes intents do not match the events granted on the open platform
Private chat works, groups do not The bot is not a group member, or the group event was not granted
40054005 on send Same msg_id + msg_seq sent twice (the plugin increments automatically)
40034128 on announcements Outside the 5 minute passive window / proactive rate limit
Linking fails The code expired (10 minutes) or was already used

Way 3: official QQ bot + OneBot v11 adapter (official adapter)

If you already run an adapter such as onebots / @onebots/adapter-qq, the plugin does not need to connect to the QQ gateway itself: the adapter wraps Tencent's official SDK (@tencent-connect/qqbot-nodejs) and exposes the official bot as OneBot v11, so the plain OneBot bridge from way 1 works.

Way 2 (direct) Way 3 (adapter)
Extra process none a Node.js process
Best for a single plugin install you already run onebots, or need several platforms
Configuration qq-official section onebot section

Steps

  1. Install Node.js 18 or newer.
  2. Start the adapter (onebots example): npx onebots -r qq, then enter the AppID / AppSecret from the QQ open platform.
  3. Enable the adapter's OneBot v11 HTTP API (onebot.v11: use_http: true in onebots), usually at http://127.0.0.1:6727.
  4. Enable OneBot in Nascraft's config.yml:
onebot:
  enabled: true
  # points at the adapter's OneBot v11 HTTP API
  api-url: 'http://127.0.0.1:6727'
  # must match the access token configured in the adapter; empty means no check
  access-token: ''
  commands:
    enabled: true
    group-whitelist: []
  webhook:
    # for passive replies and group messages the adapter must report to the plugin
    enabled: true
    host: '0.0.0.0'
    port: 8765
    path: '/onebot'
    secret: ''
  1. Restart the server; [OneBot] 已启用，API: http://127.0.0.1:6727 means it is connected.

Things to know

  • ids are strings: the official adapter reports user_id / group_id as openids (for example 0A1B2C3D4E5F...), not numeric QQ ids. Nascraft's OneBot bridge accepts both, so put openids straight into group-ids and group-whitelist; old numeric group ids keep working.
  • Guild messages are ignored: the plugin only handles group @-messages and private messages; QQ guild channels are skipped.
  • Passive replies are windowed: a passive reply to one message is valid for 5 minutes and up to 5 times; trade announcements and price alerts are proactive messages and subject to the official rate limit (60 per minute for verified bots).
  • Only the OneBot webhook uses a port: way 3 goes through the OneBot bridge from way 1, so the plugin still listens on onebot.webhook.port (8765 by default). If another bot plugin or adapter on the same machine holds that port, the startup log says 端口 127.0.0.1:8765 已被占用 — change it to a free port such as 8766 and update the adapter's report URL.
